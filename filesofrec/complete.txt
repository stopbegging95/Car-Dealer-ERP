    - On Windows, Windows Defender Application Control (WDAC) / Smart App Control blocked the native binary addon `tailwindcss-oxide.win32-x64-msvc.node` (`ERR_DLOPEN_FAILED`).
    - Tailwind v4's WASI fallback was unable to access host disk files in Node 23, resulting in 0 utility classes generated and leaving `globals.css` without compiled utility styles.
    - Missing `postcss.config.mjs` and deprecated experimental turbopack loader rules further prevented PostCSS execution.
  * Resolution & Configuration:
    - Switched to the robust, pure JavaScript PostCSS Tailwind engine (`tailwindcss@3.4.17` + `autoprefixer@10.4.20` + `postcss@8.4.49`), which requires zero native `.node` binaries and is immune to Windows application control policy blocks.
    - Created standard `frontend/postcss.config.mjs` with `tailwindcss` and `autoprefixer` plugins.
    - Created `frontend/tailwind.config.js` properly configured with `./src/**/*.{js,ts,jsx,tsx,mdx}` content glob and custom automotive theme extensions.
    - Updated `frontend/src/app/globals.css` with `@tailwind base; @tailwind components; @tailwind utilities;`, preserving custom CSS variables and automotive theme classes.
